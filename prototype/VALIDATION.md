# SkillMesh 0.7 验收记录

初次验收：2026-08-07；补齐回归：2026-08-09（Asia/Shanghai）
环境：macOS、Node.js 26.3.1、`@modelcontextprotocol/sdk` 1.30.0、`@modelcontextprotocol/ext-apps` 1.7.5、`esbuild` 0.28.2、Codex 应用内浏览器

## 结论

0.7 保留“工作流选择 → Skill 证据确认 → MCP 安装提案 → Web 人工确认 → 受控安装/扫描/复评”的闭环，并增加 Codex 对话内原生快速使用 Widget。Web、MCP 与 Widget 复用同一 `QuickSkillState v1` 和快速卡片服务，只展示“当前阶段相关 6 项、收藏 4 项、最近使用 4 项”；任务、当前 Codex 与预期产物可在 Widget 内一次填写并追加到当前任务。安装、覆盖和模板迁移等有真实后果的动作仍保留显式确认。

可信 MCP 连接会自动确保回环地址 Web 后台就绪：先健康探测并复用已有实例，端口空闲时才以独立子进程启动 `server.mjs`，外部应用占用端口时不接管。自动启动服务不等于授权安装；MCP 仍然只能创建和读取安装提案，只有用户在 Web 页面中确认后，服务端才会写入受管 Skill 路径。

自动化使用真实 stdio MCP 客户端验证三个 0.7 工具、Widget 资源 URI/MIME、结构化降级结果、状态写入和并发冲突；Web 写入的状态可由 MCP 读取。浏览器以 `window.openai` 兼容桥模拟 Widget 宿主，完成多工作流选择、收藏、表单校验、消息发送成功/失败及“消息已发送但最近记录同步失败”路径；成功路径恰好追加 1 条消息并记录 1 次使用，失败路径不记录，偏好同步失败也不重复发送。`390 × 844` 下 `scrollWidth=clientWidth=390`，宿主强制深色/浅色均生效，控制台 0 错误、0 警告。该轮还发现压缩代码作为 `String.replace` 替换字符串时，内含的替换占位序列会破坏内联脚本；构建器改用函数替换，并增加 VM 真实解析回归。

## 信任与安全边界

- MCP 与 Web 共享本机原子 JSON 存储；连接 MCP 只自动启动可视化后台，执行仍要求 Web 人工确认，不会自动获得写权限或安装 Skill。
- 外部安装仅接受解析后的包标识、固定 Agent 参数和已审阅内容指纹，使用无 shell 子进程，限制超时与输出大小。
- 本地候选执行前重新计算内容哈希；发生变化即拒绝旧计划。
- 安装前只能审阅目录映射的单份 `SKILL.md`，无法覆盖仓库其他脚本、依赖和安装时产物；Web 必须逐项确认剩余风险，安装后再扫描完整落盘目录，并对 `SKILL.md` 做审阅指纹一致性校验。
- Skill Kit 导入内容按不可信数据校验，仅与当前本机清单和既有候选比较；不会读取外部来源、创建写入或触发安装。
- 所有自动写入仅限共享目录、白名单 Agent 目录以及应用自己的日志、快照和隔离目录。
- Skill 安装后不会运行其脚本或正文指令；运行验证仍是独立、未自动化的证据轴。

## 已知边界

1. 匹配仍是确定性、可解释的文本检索启发式，不是成功概率或真实运行评测。
2. 外部安装依赖 Skills CLI 和网络；CLI 当前不提供由本项目控制的提交锁定参数，执行时仍会读取当时上游内容。SkillMesh 通过安装后比对已审阅 SHA-256 并失败关闭来检测漂移，而不是声称下载已被预先锁定；网络失败不会自动重试。
3. 安全扫描是有界静态规则，不替代沙箱、签名、供应链信誉或人工代码审查。
4. Agent 是否需要重启或重新加载取决于各 Agent 自身能力，当前只记录待加载状态。
5. 网页使用短轮询同步多进程变化，不是实时协同编辑器。
6. 样例跑通和初级开发者验证已有独立、按序、内容哈希绑定的证据记录，但 Web human actor 不是密码学身份；QA 模拟也不能替代真实外部新手研究。
7. 当前只记录人工执行、验收和证据，不自动运行项目命令、Skill 或测试。
8. Web 领域使用金标九阶段源模板，并可按复杂度压缩为 3/5 阶段；其他领域仍是通用回退，需要领域专家复核。
9. 组合链覆盖只按本机清单中的规范化精确名称判断；目录声明顺序用于保留来源语义，不证明目标 Agent 已可用、成员存在运行依赖或已经通过执行验证。
10. Skill Kit 是项目意图与差异回执，不是自动同步器或包管理锁文件；新外部项携带已审阅内容指纹，缺指纹的旧候选不可安装，即使本机存在同名 Skill，也仍需独立核验来源与内容。
11. SkillMesh 已在当前 Codex 安装并启用，安装缓存的 MCP/Web/Widget 资源已实测；Codex 不会为当前任务热加载新插件，仍需在新任务中完成一次真实原生渲染和 `ui/message` smoke test。
