# SkillsMap 项目入口

本项目已经完成“市场与生态调研 → 本机 Skill 清单 → 共享工作流持久化 → stdio MCP + Codex 原生 Quick Use Widget → 自动项目概况 → 3/5/完整深度执行方案 → 单次执行基线锁定 → 执行与分级验证记录 → Skill 受控安装 → 重新扫描与复评”的闭环。

默认扫描共享根，以及 Codex、Claude Code、Cursor、Gemini CLI、Antigravity、Kiro、Trae、OpenCode、WorkBuddy、QoderWork、OpenClaw 等已知用户/项目 Skill 根；同一内容出现在多个 Agent 下时只计一项能力，但会保留全部 Agent 与 Provider 归属。网页“本机事实”会显示作用、显式 triggers、调用声明和保守调用提示；完整 `SKILL.md` 只在用户点击后读取单份限量原文。

- 可运行工具：[SkillMesh 0.7](./prototype/README.md)
- macOS 双击启动：[启动技能测绘台.command](./prototype/启动技能测绘台.command)
- 功能与安全验收：[0.7 验收记录](./prototype/VALIDATION.md)
- 市场、竞品与 Agent 生态调研：[完整调研报告](./agent-skill-workflow-map-research/report.md)

工具默认只监听 `127.0.0.1`，通过本机 stdio MCP 接受 Agent 草案并统一保存历史。可信 MCP 连接会自动探测并托管独立的 Web 后台；`open_web_ui` 只在用户明确要求时打开浏览器。MCP 可协助建立工作流、项目概况、执行方案草案和安装提案；工作流确认、概况锁定和方案确认已合并为网页中的一次“锁定基线并开始执行”。安装写盘仍需单独人工确认，系统不会自动运行 Skill 或项目命令。

## 当前项目的实际使用流程

### 1. 首次启动与连接

1. 进入 `prototype`，运行 `npm install` 和 `npm start`；需要 PDF 时再运行 `npm run setup:pdf`。
2. 打开 <http://127.0.0.1:4317>，或在 macOS 双击 [`启动技能测绘台.command`](./prototype/启动技能测绘台.command)。
3. 将 [`mcp-server.mjs`](./prototype/mcp-server.mjs) 配置到 Codex、Claude Code 或 Gemini CLI。MCP 与网页必须使用同一数据目录，才能看到相同的工作流、Brief、手册和确认历史。

完整命令和 Host 配置见 [`prototype/README.md`](./prototype/README.md#启动网页)。

### 2. 由 Agent 建立工作流草案

网页不通过一段自然语言直接创建工作流。用户先在 Agent 对话中描述项目目标，由 Agent 通过 MCP：

1. 调用 `create_requirement_workflow_draft` 保存结构化需求，并选择 Web、Android 或通用参考流程。
2. 调用 `atlas_status`、`search_skills` 和 `assess_workflow`，把每项能力与本机可用 Skill 对应起来。
3. 系统随工作流自动建立并补齐项目概况；只有推断不准确时才调用 `update_project_brief_draft` 调整。

草案写入共享工作区后，网页会自动发现；用户在左侧“当前工作流”中选择它。

### 3. 在网页确认能力与 Skill 映射

用户逐阶段查看必需能力和本机候选，并对候选执行“确认、部分、排除或待确认”。这里确认的是“这个 Skill 是否适合覆盖该能力”，不是证明 Skill 已经运行成功。

只有人工确认的本地匹配会成为手册中的可靠主选；证据不足的候选仍会标成“待确认”，缺失能力则保留人工回退和可选的外部 Skill 搜索路径。

界面和导出分别显示“文本证据覆盖”与“人工确认覆盖”。名称、description 或正文命中只能提高前者，不能自动成为手册主 Skill，也不能被解释为运行成功。

### 4. 核对自动生成的项目概况

进入网页“执行方案”，系统已经从工作流推断项目名、问题、用户、结果、范围、非目标、约束、成功标准、平台和技术栈。默认只展示三个核心字段，其余信息按需展开；修改会自动保存。

项目概况保持草稿时也能生成和反复调整执行方案，不需要先保存或冻结。

### 5. 生成并审阅执行方案

Agent 或网页显式生成 Playbook。默认按风险与交付目标自动选择深度：精简方案最多 3 阶段、标准方案最多 5 阶段，生产或高风险项目保留完整专家流程；用户也可以手动切换。生成结果为每个阶段和步骤明确：

- 本阶段的 Skill 执行地图；
- 每一步的主 Skill、备用 Skill、确认状态与负责范围；
- 主 Skill 必须持续使用到什么程度，备用 Skill 何时才可替代；
- 必须交付的产物、验收标准和必须保存的证据；
- 满足哪些条件后才能进入下一阶段；
- Skill 不可用或匹配不足时的人工回退方式。

通用操作建议、调用提示词和失败恢复仍然保留，但收在步骤的折叠参考区，不代替 Skill 完成尺度和阶段门。

### 6. 一次锁定执行基线

用户审阅当前方案后点击“锁定基线并开始执行”。系统用一次动作统一保存工作流版本、项目概况版本、执行方案版本和进度会话，不再分别要求工作流确认、Brief 冻结、手册确认和“开始记录进度”。后续修改仍会创建新草稿，不会改写旧基线。

如果九阶段模板的版本或内容指纹发生变化，必须按“预览模板迁移 → 应用为新草案 → 重新审阅 → 人工确认”处理。系统不会静默覆盖旧版本、旧进度或旧验证证据。

### 7. 按阶段执行手册

锁定后，项目概况与版本设置默认折叠，页面会直接展开当前可执行阶段。每个步骤按以下顺序执行：

1. 先查看步骤顶部的“本步使用”，确定主 Skill、待确认建议或人工回退；备用 Skill 和能力缺口按需展开。
2. 使用主 Skill 完成其“负责范围”；只有主 Skill 不适用或证据不足时，才使用备用 Skill。
3. 持续执行到“做到什么程度才算完成”的全部条件满足。
4. 点击“完成这个步骤”或“完成并进入下一阶段”。软门可直接完成；硬门只需在同一处填写一次结果、产物说明或证据链接。
5. 系统会在一次写入中记录“步骤已完成 + 验收通过”，本阶段全部步骤满足条件时自动通过质量门并展开下一阶段，不再要求重复填写质量门理由。
6. 页面只直接展示当前阶段；已完成和等待中的阶段收在一个阶段记录入口。只有遇到进行中、失败、返工、手动改门或阶段不适用等例外时，才展开“修正/手动调整”。

不适用阶段不能直接删除，必须保留最低判断并记录原因。重新生成手册后，旧内容哈希下的进度仍保留，但不会自动套到新版本。

### 8. 验证、导出与迭代

1. 所有适用步骤和质量门完成后，点击顶部“记录样例已跑通”会直接进入验证；默认只填写结论和证据，样例名与项目上下文已按执行基线预填，环境不同或存在阻塞时再展开修正。
2. 再由初级测试者按手册独立执行，填写匿名测试者画像、结论和证据；协助程度与阻塞项按需展开，升级为“初级开发者已验证”。
3. 从网页导出 Markdown 或 PDF。两种格式都来自同一个 Playbook，并携带其精确项目概况快照、来源、内容哈希和验证状态。
4. 项目目标、Brief、模板或 Skill 映射发生实质变化时，创建新草案并重新走审阅、确认与验证流程。

### 9. 可选：补齐缺失 Skill

只对明确缺失的必需能力搜索外部 Skill。用户可从能力缺口直接进入网页“生态候选”目录，按功能、来源和组合关系筛选 Skills Atlas 的公开元数据；同一功能组存在多个仓库时，可横向核对许可证、更新时间、热度、安装映射与可绑定 Skill。组合链详情会按目录声明顺序逐项核对本机精确名称覆盖、当前缺口已记录项和待补项，并可把已逐项审阅的待补成员作为一次原子元数据变更批量记录；链名、组名与成员位置会随候选保存，但目录顺序不等于项目依赖或运行验证。记录可安装候选前必须显式读取目录映射的单份 `SKILL.md`，核对仓库、分支、路径、SHA-256、frontmatter、工具声明、带行号原文和静态风险线索；服务端会再次核对并把该 SHA-256 绑定到候选。缺少审阅指纹或出现高/严重线索时不能进入安装集合；安装后实际内容与审阅指纹不一致时会立即断链并隔离。MCP Agent 只能追加 `suggested` 搜索线索，接受候选和安装执行仍是网页人工动作；系统不会自动安装或执行。

安装选择保存后，可下载 `capability-atlas.skill-kit.json` 作为项目可提交的 Skill 意图清单。Kit 用稳定 SHA-256 绑定工作流、目标 Agent、能力覆盖和所选本地/外部 Skill，但不携带绝对路径、安装命令或确认人信息。导入 Kit 只会核对“内容一致、本地有改动、已禁用、已有候选、缺失”等状态；不会创建候选或安装计划，也不会安装、移除或清理未声明的本机 Skill。

## Agent 与网页的职责边界

| 环节 | Agent / MCP | 网页用户 |
|---|---|---|
| 工作流与项目概况 | 创建草案、自动补齐、生成方案预览 | 必要时调整，并在正式执行时一次锁定基线 |
| Skill 映射 | 扫描、检索、评估、提出候选 | 确认、部分确认或排除候选 |
| 执行方案 | 生成 3/5/完整深度草案、读取差异、导出 Markdown | 审阅差异、迁移模板、锁定执行基线 |
| 执行与质量门 | 只读进度和验证状态 | 执行 Skill；一次完成步骤与验收，硬门补一次证据，例外时再手动修正 |
| Skill 安装 | 搜索候选、提出安装计划 | 审核风险并显式执行安装 |
| 项目 Skill Kit | 无自动同步或执行权限 | 导出意图清单、导入并只读核对本机状态 |

核心原则：Agent 负责提案和编排，网页负责会改变可信状态的人工确认；SkillMesh 本身不自动运行 Skill、开发命令或测试命令。
